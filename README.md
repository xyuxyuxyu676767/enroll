# Запись на курс

Чтобы попасть в классрум курса, не нужны формы и списки: открой заявку по
кнопке **New issue → Записаться на курс**, выбери группу, впиши фамилию и имя.
Заявка уходит от твоего GitHub-аккаунта, поэтому логин бот знает сам.

Через несколько минут бот ответит в заявке: пришлёт приглашение в организацию
и ссылку на лабу 0. Открой ссылку, нажми **Accept assignment**, и у тебя
появится свой репозиторий для лабы.

---

## Для преподавателя

Этот репозиторий публичный, потому что студент ещё не в организации и иначе
не сможет открыть заявку. Обработка идёт в `.github/workflows/enroll.yaml`
на каждую новую заявку плюс раз в час; каждый запуск разбирает все открытые
заявки сразу, поэтому одновременные запуски безопасно отменяются.

Что делает бот на каждую заявку:

1. Берёт группу из выпадающего списка (единственный источник списка групп:
   `.github/ISSUE_TEMPLATE/enroll.yml`, поле `group`).
2. Отправляет приглашение в организацию с прикреплённой командой классрума.
   Для того, кто уже в организации, просто добавляет в команду классрума.
3. Дописывает строку в `classroom50/<classroom>/roster.csv`: логин, имя,
   `section` = группа, `github_id`, роль `student`. Одним коммитом на запуск.
4. Отвечает в заявке ссылкой на accept лабы 0, закрывает и блокирует её.
   Заявка с ошибкой (группа не из списка, приглашение не ушло) получает
   метку `needs-attention` и остаётся открытой.

### Установка

```sh
./install.sh <org>
```

Создаёт публичный репозиторий `<org>/enroll` с этими файлами и метками.
Дальше руками:

1. В `.github/workflows/enroll.yaml` поправь `CLASSROOM` и `ACCEPT_SLUG`.
2. В `.github/ISSUE_TEMPLATE/enroll.yml` впиши свои группы.
3. Создай fine-grained PAT от владельца организации (Resource owner =
   организация): **Organization → Members: Read and write**; **Repository
   `classroom50` → Contents: Read and write**. Положи в секрет `ENROLL_TOKEN`
   репозитория `enroll`.
4. Прогони **Actions → Enroll → Run workflow** с `dry_run`, чтобы убедиться,
   что токен читает `classroom.json` и `roster.csv`.

### Что проверить перед потоком в 300 человек

- Лимит приглашений GitHub в сутки на организацию. Заявки, которые не
  прошли, остаются открытыми с меткой `needs-attention`, и следующий запуск
  (в течение часа) пробует снова. Ничего не теряется, но первый день может
  идти волнами.
- Организация на плане Team (через GitHub Education) и число мест.
- Фамилия и группа видны в публичной заявке. Если это нежелательно, поставь
  `DELETE_ISSUES: "true"`: после ответа бот удаляет заявку (нужен токен
  владельца с правом на удаление issue), а студент получает ответ письмом.
